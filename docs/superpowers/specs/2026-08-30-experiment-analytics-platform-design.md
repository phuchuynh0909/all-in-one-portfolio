# Experiment Analytics Platform — Design

Date: 2026-08-30
Status: Approved, ready for implementation planning

## Problem

Backtest experiments live in `notebooks/backtest_*.ipynb`. Each run's results
exist only as printed cell output and ad-hoc HDF5 files
(`backtest_008_results.h5`, `backtest_009_results.h5`,
`all_trades_with_features.h5`). Nothing is comparable across notebooks, nothing
survives a kernel restart in queryable form, and the trade-level analysis in
`winner_loser_explorer.ipynb` / `t_loser_autopsy.ipynb` has to be re-run by hand
against whichever notebook last wrote the H5.

Two jobs the platform must do:

1. **Drill into one experiment** — equity, per-symbol stats, the trade list,
   entry/exit markers on price.
2. **Trade-level attribution** — pool trades and slice by symbol, outcome
   bucket, holding period, exit reason, and entry features, to find where the
   edge comes from.

Explicitly *not* the goal: a strategy leaderboard, or an Optuna trial explorer.
Those are possible later on the same data but are not designed for here.

## Approach

Parquet is the durable artifact; a DuckDB database file holds **views only**
over that Parquet, giving single-database ergonomics in notebooks without a
second copy of the data. The React app never talks to a backend for experiment
data — it reads the same Parquet directly with DuckDB-WASM over HTTP.

Rejected alternatives:

- **Parquet-only.** Same robustness, but notebook analysis means retyping
  `read_parquet('...')` paths; no single database to point DuckDB at.
- **One real DuckDB file as the store.** Cleanest mental model, but every run
  republishes the whole file, remote `ATTACH` in WASM is less proven than the
  Parquet path, and concurrent notebook writes contend on DuckDB's single
  writer lock.

The chosen split has a benign worst case: the `.duckdb` file holds no data, so
a stale or deleted one is regenerated by one call and losing it costs nothing.

## Architecture

```
notebook                      published dir                      browser
--------                      -------------                      -------
pf (vectorbt)
  |
  | log_experiment(pf, ...)
  v
ExperimentStore --writes-->  runs/<run_id>/trades.parquet
  |                          runs/<run_id>/symbol_stats.parquet
  |                          runs/<run_id>/equity.parquet
  |                          runs/<run_id>/meta.json
  |                          catalog.json          <-- run list
  |
  +--rebuilds-->             experiments.duckdb    (views only, local use)
                                    ^                        |
                                    |                        | fetch catalog.json
                             notebook ad-hoc SQL             | then DuckDB-WASM
                                                             v  over the file list
                                                       Experiments page
                                                       (+ OHLC from existing /api/v1)
```

Three independently testable units:

| Unit | Location | Responsibility | Depends on |
| --- | --- | --- | --- |
| `ExperimentStore` | `backend/app/services/experiments/store.py` | Write path, catalog, view rebuild | storage backend |
| `log_experiment()` | `backend/app/services/experiments/adapter.py` | Extract the three tables from a vectorbt `Portfolio` | vectorbt, store |
| `experimentsDb` | `frontend/src/lib/experiments/` | DuckDB-WASM lifecycle + typed query surface | `@duckdb/duckdb-wasm` |

`adapter.py` is the **only** file that touches vectorbt's API. A vectorbt
upgrade changes one file.

### Hard constraint: no HTTP globbing

DuckDB's httpfs cannot glob over HTTP — there is no directory listing. The
browser therefore fetches `catalog.json` first and passes DuckDB an explicit
file list. The notebook side, on a real filesystem, globs freely. This is why
the catalog is a first-class artifact rather than a convenience index.

### Scope of "browser-only"

Only the experiment store is serverless. Price data for chart overlays still
comes from the existing FastAPI app at `/api/v1`.

## Storage layout

```
data/experiments/               # gitignored; symlinked to frontend/public/experiments in dev
  catalog.json
  experiments.duckdb
  runs/<run_id>/
    meta.json
    trades.parquet
    symbol_stats.parquet
    equity.parquet
```

`run_id` = `{name}__{YYYYMMDDTHHMMSS}__{params_hash[:6]}` — sortable, readable,
and distinct across re-runs with different params.

### `catalog.json`

JSON, not Parquet: `params` is a nested dict, and the run picker must render on
one plain `fetch` without paying for the WASM bundle.

```json
{
  "schema_version": 1,
  "runs": [
    {
      "run_id": "backtest_012_gframa_hbo__20260830T142233__a1f3c9",
      "name": "backtest_012_gframa_hbo",
      "created_at": "2026-08-30T14:22:33Z",
      "tags": ["oos", "optuna", "balanced"],
      "params": { "gaussian_length": 6, "hbo_mult": 2.5 },
      "data_start": "2019-01-01",
      "data_end": "2026-08-29",
      "oos_start": "2023-07-14",
      "n_symbols": 312,
      "n_trades": 8417,
      "equity_agg": "mean",
      "metrics": {
        "mean_total_return": 0.42,
        "mean_sharpe": 1.18,
        "pct_symbols_positive": 0.63
      },
      "source": {

      },
      "files": {
        "trades": "runs/backtest_012_gframa_hbo__20260830T142233__a1f3c9/trades.parquet",
        "symbol_stats": "runs/backtest_012_gframa_hbo__20260830T142233__a1f3c9/symbol_stats.parquet",
        "equity": "runs/backtest_012_gframa_hbo__20260830T142233__a1f3c9/equity.parquet"
      }
    }
  ]
}
```

`catalog.json` is **derived**, never authoritative. Each run writes its own
`meta.json`; the catalog is their concatenation. Two notebooks finishing at once
cannot corrupt anything permanent — worst case the catalog misses a run, and
`store.rebuild_catalog()` rescans the run directories and repairs it. Local
writes additionally take an `fcntl` lock on the catalog to make that rare.

### `trades.parquet` — the fact table

| Column | Type | Notes |
| --- | --- | --- |
| `run_id` | VARCHAR | |
| `trade_id` | BIGINT | vectorbt exit-trade id, unique within run |
| `symbol` | VARCHAR | |
| `entry_dt` | TIMESTAMP | |
| `entry_price` | DOUBLE | average entry price |
| `exit_dt` | TIMESTAMP | NULL while open |
| `exit_price` | DOUBLE | NULL while open |
| `size` | DOUBLE | |
| `pnl` | DOUBLE | |
| `ret` | DOUBLE | gross return, before fees |
| `net_return` | DOUBLE | after fees — **the primary outcome column** |
| `bars_held` | INTEGER | from `exit_idx - entry_idx` |
| `direction` | VARCHAR | |
| `status` | VARCHAR | `closed` / `open` |
| `exit_reason` | VARCHAR | **nullable** — vectorbt does not record this natively; the adapter fills it only when stop-loss information is supplied |
| `feat_*` | DOUBLE | caller-supplied entry features, prefixed so pooling never collides with core columns |

Cross-run pooling uses `read_parquet([...], union_by_name=true)`, so runs with
different feature sets pool cleanly and absent features read as NULL.

### `symbol_stats.parquet`

`run_id, symbol, n_trades, total_return, sharpe, sortino, max_drawdown,
win_rate, avg_win, avg_loss, profit_factor, expectancy, exposure`.

Infinities and NaNs are normalised to NULL at write time (matching the existing
`_clean` idiom in the notebooks) so SQL aggregates behave.

### `equity.parquet`

`run_id, dt, value, returns, drawdown, benchmark_value` — `benchmark_value` is
nullable and holds e.g. VNINDEX buy-and-hold when supplied.

**Equity is a composite, and is labelled as one.** The notebooks call
`from_signals(..., cash_sharing=False)`, so each symbol is an independent book —
which is why `pf.total_return()` returns a Series that gets `.mean()`d. There is
no true portfolio equity curve to extract. `equity.parquet` therefore stores the
equal-weight composite (mean of the per-symbol value curves), and `meta.json`
records `equity_agg` so the UI labels the axis honestly rather than implying a
traded portfolio. If a genuinely cash-shared `Portfolio` is passed, the adapter
detects the single group and stores it directly, setting `equity_agg` to
`"portfolio"`.

### Deliberate omissions

- **Outcome buckets are not stored.** The `1_catastrophic_loss` …
  `5_big_win` segmentation is a quantile cut computed in SQL at query time, so
  the cut points can be changed, or applied per-symbol instead of pooled,
  without rewriting any file.
- **Feature-discrimination statistics are not stored** — same reasoning.
- **No pooled `trades.parquet`.** Reading N run files is fine at the expected
  scale. If it becomes slow, adding a pooled build step is a contained,
  additive change.


### `adapter.py`

- Trade fields from `pf.trades.records_readable`; `entry_idx` / `exit_idx` from
  the raw `pf.trades.records` for `bars_held`.
- Per-symbol statistics from `pf.total_return()`, `pf.sharpe_ratio()`,
  `pf.sortino_ratio()`, `pf.max_drawdown()`, `pf.trades.win_rate()`,
  `pf.trades.profit_factor()`, `pf.trades.expectancy()`.
- vectorbt renames `records_readable` columns between versions, so the adapter
  carries an **explicit column-name map** and raises on an unmapped column.
  Silently writing NULLs is not acceptable.
- `features` is joined on `(symbol, entry_dt)`; every joined column is prefixed
  `feat_`. A supplied column that would collide with a core column after
  prefixing is an error, not a silent overwrite.

### `store.py`

- `ExperimentStore.from_env()` reads `EXPERIMENTS_BACKEND` (`local` | `r2`) and
  `EXPERIMENTS_DIR`.
- `write_run(...)` → Parquet + `meta.json`, then catalog update, then
  `rebuild_views()`.
- `rebuild_catalog()` → rescan `runs/*/meta.json`, rewrite `catalog.json`.
- `rebuild_views()` → regenerate `experiments.duckdb` with four views:
  `runs` (via `read_json_auto` of the catalog), `trades`, `symbol_stats`,
  `equity` (via filesystem globs with `union_by_name=true`).

### `backends.py`

A four-method protocol — `write_parquet`, `write_json`, `read_json`,
`base_uri`. `LocalBackend(root)` ships now. `R2Backend(bucket, prefix)` is
deferred; the protocol exists so adding it touches one file. Do not build the
R2 backend as part of this work.

### Notebook usage

```python
import duckdb
con = duckdb.connect("data/experiments/experiments.duckdb", read_only=True)
con.sql("SELECT run_id, avg(net_return) FROM trades GROUP BY 1")
```

## Browser query layer

`frontend/src/lib/experiments/`:

- `catalog.ts` — plain `fetch` of `catalog.json` through TanStack Query. The run
  list renders without loading DuckDB at all.
- `db.ts` — lazily instantiated DuckDB-WASM singleton behind a dynamic
  `import()`, so the ~3 MB WASM bundle is fetched only on entering the
  Experiments route and never on Portfolio, Chart, or any other page.
- `queries.ts` — the typed surface. Components call these; **no raw SQL in
  components.**

```ts
getSymbolStats(runId)
getEquity(runId)
getTrades(runId, filters)
getOutcomeBuckets(runIds, quantiles)
getFeatureDiscrimination(runIds, bucket)
```

Parquet files are registered with `registerFileURL(..., DuckDBDataProtocol.HTTP)`
so DuckDB issues range requests and reads only the column chunks a query needs —
a `feat_*` scan does not pull price columns. Pooled queries take their explicit
file list from the catalog and use `union_by_name=true`.

Feature discrimination is a single `UNPIVOT` over the `feat_*` columns plus a
grouped mean/std per outcome bucket, so it works on any strategy's feature set
with no hardcoded column list.

## UI

New route `/experiments`, page `frontend/src/pages/Experiments.tsx`, in the
existing app shell alongside Backtest and Regime.

```
+- runs ----------+------------------------------------------------------+
| [search] [tags] |  backtest_012_gframa_hbo . 2026-08-30 . oos, optuna   |
|                 |  [ Overview | Trades | Attribution | Symbol ]         |
| > 012_gframa    |                                                       |
|   2026-08-30    |  Overview:                                            |
| > 011_pearson   |    composite equity vs VNINDEX B&H                    |
|   2026-08-28    |    mean ret . mean sharpe . % symbols + . n trades     |
| > 005g_regime   |    params table (diffable against another run)        |
|   2026-08-21    |    per-symbol stats - sortable, click -> Symbol tab    |
|                 |                                                       |
| [ ] compare  <--+-- multi-select feeds the Attribution tab              |
+-----------------+------------------------------------------------------+
```

- **Overview** — composite equity plus benchmark, headline metrics, params,
  sortable `symbol_stats`.
- **Trades** — full trade table, filterable by symbol, date, outcome bucket and
  `exit_reason`; rows tinted by bucket. Quantile cut points are adjustable in
  the UI because they are computed at query time.
- **Attribution** — bucket distribution, feature-discrimination ranking, per-
  feature winner-vs-loser distributions, and slice-by symbol / month /
  `bars_held` / `exit_reason`. Honors the run multi-select, pooling trades
  across runs. The discrimination table shows per-feature **coverage %** so a
  three-run signal is not misread as a thirty-run one.
- **Symbol** — one symbol's OHLC from the existing `/api/v1` rendered with
  `lightweight-charts`, with entry/exit markers overlaid from `trades`.

Distributions and bar charts use `recharts`; price uses `lightweight-charts`.
Both are already dependencies. The only new frontend dependency is
`@duckdb/duckdb-wasm`.

## Failure modes

| Failure | Behavior |
| --- | --- |
| Adapter meets an unmapped vectorbt column | Raise at log time. Never write a silently-NULL column. |
| `catalog.json` missing or stale | Empty state naming the fix: `store.rebuild_catalog()` |
| A run's Parquet 404s | That tab errors; other tabs and other runs keep working |
| Pooled runs with disjoint features | `union_by_name` yields NULL; discrimination table shows coverage % |
| Server without range-request support | DuckDB falls back to whole-file fetches — correct, slower. nginx and Vite both support ranges. |
| WASM blocked or unsupported | Explicit message, not a blank tab |
| Two notebooks logging concurrently | Per-run files are independent; catalog is repaired by `rebuild_catalog()` |

## Verification

Per `AGENTS.md`, bind each change to a check that fails when the numbers are
wrong.

- `cd backend && pytest tests` — new `backend/tests/test_experiments_*.py`,
  built on a tiny synthetic vectorbt `Portfolio` fixture: deterministic,
  offline, no `load_stocks`, no DNSE. Covers extracted schema and dtypes,
  `feat_` prefixing and collision, `rebuild_catalog()` after deleting the
  catalog, and a DuckDB round-trip reading back what was written.
- **The binding assertion:** a trade's `net_return` in the store equals the
  corresponding value in `pf.trades.records_readable`. If the adapter drifts,
  this fails.
- `cd frontend && npm run build` (tsc + vite build) and `npm run lint`.
- A query-layer test against a small checked-in fixture Parquet.

## Scope boundaries

In scope: the store, the vectorbt adapter, the DuckDB view file, the browser
query layer, the Experiments page, and wiring `log_experiment()` into one or two
notebooks as proof.

Out of scope for this work:

- The R2 storage backend (protocol only; local backend ships).
- Retrofitting all `backtest_*` notebooks — new runs only, retrofit as
  notebooks are next touched.
- Strategy leaderboard and Optuna trial explorer.
- Per-symbol equity curves and per-bar signal/indicator series.
- A pooled `trades.parquet` build step.
